# ADR-0012：0.2.0 起启动门槛收束为本轮准备预算口径

状态：已接受（2026-11-24）。

## 背景

首版验收在 #44/#64 使用“用户点击启动 → 首次稳定短句”P95 ≤3 秒作为启动门槛；ADR-0009 曾把 PR89 预览候选放宽到 5.5 秒，并把 3 秒保留为未来目标。实测显示该等待主要由识别服务提供首个完整短语决定：中文 +4274.3 ms、英文 +3272.2 ms，应用显示只增加 4/26 ms。40 次真实启动的中文 P95 为 10.5135 秒、英文 5.9663 秒，均无法在 3 秒内完成。

ADR-0010（2026-11-16 用户接受）把体验方向改为优先完整句，确认 6 秒句末等待、10 秒直播起播前准备、15 秒首次字幕准备和累计 2 秒播放故障等待。0.2.0 按该预算发布：开播被有意推迟，点击 → 首条字幕的耗时因此包含设计内的准备时间。继续把 3 秒/5.5 秒当作 0.2.0 的 gate，会与已接受的产品决定直接冲突。

## 决策

1. “点击 → 首次稳定字幕”P95 ≤3 秒（#44、#64）与 PR89 预览的 5.5 秒门槛，仅适用于其历史候选和预览范围；自 0.2.0 起不再作为新候选的启动 gate。
2. 0.2.0 起的启动由 ADR-0010 的预算承担，并分别报告：点击 → `ready`、`ready` → `playing`、首条字幕可见的媒体时间、直播起播前准备的媒体余量，以及播放中故障累计等待。首次准备上限 15 秒；超过预算时按 #100/#102 的规则提交全部稳定文本，或在无稳定内容时给出可行下一步。
3. 识别服务侧延迟（语音起点 → 首个完整稳定短语）作为已知限制继续单独报告；中文约 +4.3 秒、英文约 +3.3 秒的实测不因口径变更而消失，也不得写成通过。
4. 3 秒目标保留为 provider 或模型变化后的复测目标（沿用 ADR-0009 第 1 条），不用于判定 0.2.0。
5. 原 40 次启动、单例 8.0929/4.5541 秒记录及其失败结论，保留原候选、输入与日期范围，不重新解释为通过。

## 影响

- #44 的 20 次启动条目按上述口径重述；中英各 30 分钟直播、前后 5 分钟延迟增长、支持矩阵与来源缺口不变。
- #64 的“诊断首稳定字幕延迟并执行两语 20 次启动”已于 2026-10-27 完成并留证；其阈值判定由本 ADR 收束，0.2.0 起的启动记录归 #103 的真实候选对比。
- #34/#46 的发布门槛按“已知限制发布”的事实改写；同步、覆盖与长时观看门槛不变。
- 本决策不授予任何产品、同步、覆盖或发布通过，也不改变 ADR-0010 的 6/10/15/2 秒预算。
