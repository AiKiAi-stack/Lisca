# ADR-0002: 字幕显示模型 v2——固定窗口分块（取代 ADR-0001 显示部分）

- 状态：已取代（2026-10-17；见 ADR-0003）
- 关联：ticket-13（issue #15）
- 取代：ADR-0001 的「字级渲染」显示部分（words 数据管线保留，仅显示模型变更）

## 背景

ADR-0001 的字级流式渲染经用户真实使用复验后不被接受：逐字输出观感不佳；
快语速/断句不明显时单句无限累积。用户期望的是**普通字幕**形态：
固定窗口内音频内容**完整**显示，窗口到点要么消失（无人说话）要么下一窗口完整出现。

## 决策

1. **固定窗口分块显示**：窗口 = 播放时间片 `[kD, (k+1)D)`（D 可调，1-4s，默认 4s）。
   显示该窗口内所有字级时间戳落入窗口的完整文本；窗口内无字 → 空白。
2. **窗口时长可调**：新增「字幕窗口」控件（1/2/3/4s）；「断句」控件保留
   （服务端分段仍影响历史区质量与 API 负载）。
3. **字幕开关**：中间字幕显示可关闭/开启（同日志按钮，默认开）。
4. **words 管线保留**：分块由字级时间戳聚合（转写时间轴领先播放，当前窗口的字
   必然已转写，故窗口内容总是完整可用）。

## v4 定案（ticket-15 / issue #17，2026-08-09 复验修订——直播延时技术）

用户两次复验否决 v3（滞后 [2,6]s → [1,3]s 仍明显）。定案采用**直播延时播放**标准做法：
**视频播放比源延迟 N 秒，转写实时跑——播放位置的字早已转写，字幕直接显示当前窗口，
完整且与画面同步，无显示侧滞后**。

1. **播放就绪 = 转写覆盖满第一个窗口**：后端跟踪转写覆盖度（emit 的字级最大 end），
   `coverage ≥ D+1s` 发 `{type:ready}`（开场静音按 `fed ≥ D+4s` 兜底），前端收到 +1.5s 才 play。
2. **显示当前窗口**：`w0 = ⌊t/D⌋·D`，窗口 [w0, w0+D) 内容在窗口起点快照冻结——
   无 guard、无显示侧滞后；每块恰好显示 D 秒，到点整体切换。
3. **快照冻结**：窗口起点对 subs 字级数据快照一次冻结到窗口结束——API partial
   字级时间戳随修正漂移会导致实时聚合闪变，冻结从构造上保证「块内零变化、不流式」。
4. **words 替换语义**：partial 携带累计 words（已诊断确认），整体替换不含旧修订残留。

代价：视频/直播内容相对源延迟约 N+1.5s（延时直播的固有代价，用户接受）；字幕与画面同步。

## 后果

- 显示更新节奏 = 窗口边界（每 D 秒一次整体切换），窗口内文本稳定——无逐字跳动。
- 窗口与句子/断句解耦：断句不明显不再导致字幕无限变长（滚动尾窗不再需要）。
- 验收：窗口内文本稳定、边界整体切换、无说话窗口空白；repro 断言改为分块语义。
