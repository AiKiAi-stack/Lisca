# ADR-0003: 按句时间轴显示字幕与可调直播延迟

- 状态：已接受（2026-10-17）
- 取代：ADR-0002 的固定窗口显示与固定启动延迟

## 背景

直播 ASR 会持续修订同一句的文本和时间戳。固定显示窗口会把字幕行为和句子断句混在一起，
而短的固定启动延迟也不足以保证长句在播放到达前完成修订。用户更重视字幕按音源语句完整出现、
持续到语句结束，并在结束后消失。

## 决策

1. 提供直播播放延迟选项 100ms、1s、5s（默认 1s），以 ASR 已覆盖的时间位置为基准启动视频。
   延迟越长，API 越有时间补全并修订字幕；断句灵敏度仍由独立的 API 参数控制。
2. 对当前播放时间 `t`，显示满足 `beg <= t < end` 的完整识别句；收到同句 partial 修订时原地更新，
   修订后的起止时间也立即生效。句子结束后字幕自然清空或切换到下一句。
3. 保留历史区作为 ASR 输出记录，不用历史列表顺序决定画面字幕。
4. 静音期间若 ASR 没有给出覆盖度，使用已送入识别的音频进度作为启动兜底，避免等待永不结束。

## 后果

- 直播可通过延迟选择字幕完整度与实时性的平衡；100ms 适合低延迟，5s 为修订留出更多余量。
- 字幕的出现、持续和消失跟随 ASR 语句时间戳，不再按固定窗口切换。
- 延迟较大的选择会让视频和声音更晚播放，这是换取字幕完整性的预期行为。
