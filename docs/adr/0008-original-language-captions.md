# ADR-0008：优先原语言字幕，暂停界面的跨语言翻译

- 状态：已接受（2026-10-22 用户以 uploads/output.mp4 的实际错误反馈明确调整方向）。
- 范围：默认 WebUI 与默认云端会话。保留旧翻译接口的显式调用兼容性（必须传 mode: translate；仅有 source/target 不会启用翻译），但页面、默认会话及连接检查不创建翻译器。

## 背景与决策

用户截图中，约 23 秒的中文“我们还是很期待的”被显示为早先语句的英文，界面还显示译文滞后 14.4 秒。翻译调用和独立阅读队列不符合当前优先需求：中文语音输出中文字幕，英文语音输出英文字幕。

1. 默认模式是 transcribe。不设置 language_hints 时由 FunASR 自动识别语种；高级设置可以显式提示中文或英文。仅生成识别原文，不把原文交给 Qwen-MT。连接检查也只初始化识别服务。
2. 页面移除翻译方向、翻译 Key 和双语选择，使用“生成字幕”“原文字幕”措辞。云端音频传输与计费提示保留。
3. 原文不进入 ADR-0007 的译文阅读队列，按实际语音时间显示完整短句，使用识别返回的词时间切分长句。草稿仅更新记录；画面只显示终稿或重复稳定的完整短句。不会为满足固定停留时间而把旧原文排到后续语音上。
4. 本地文件可以提前向识别器提供音频，收到可显示的字幕后启动播放，后续结果继续处理。初次处理存在实际等待；它不同于播放过程中字幕持续落后。当前用户的 30.12 秒样本在一次实测中约 8.1 秒识别完成，不把这一结果推广到大文件。
5. 识别期间的播放上限沿用字幕就绪保护；没有把固定数秒或十几秒延迟定义为产品目标。实时来源仍使用流式识别。完整本地字幕生成后，暂停、继续与跳转直接使用已有时间轴，不重新发起计费会话。
6. ADR-0007 的翻译阅读队列仅保留为历史翻译模式兼容实现，不作为原文字幕的调度策略。后续重新开放翻译须另外验收真实语音、识别、翻译与画面时间的一致性。

## 验证与限制

- 原始失败：默认 HTTP 会话在缺少翻译目标时返回 400；新增中文、英文用例先复现，再验证原样输出且禁止创建翻译器。
- 用户原文件 output.mp4：真实 FunASR 自动识别，无翻译事件；5.1204 秒显示“别太装”，23.7948 秒显示“我们还是很期待的”。在播放器完成跳转后，画面烧录字幕与新叠层对应。
- 英文固定样本：真实返回英文原文，无中文译文、无翻译事件。
- 本机证据位于 logs/original-caption-acceptance（忽略目录），包括原始事件、词时间、两处截图及浏览器状态记录。
- 不宣称识别逐字零错误；例如输入结尾的截断语音仍可能识别不全。大文件性能、长期直播与发布准备仍需独立验证。

自动语种参数依据：[阿里云 FunASR 客户端事件](https://help.aliyun.com/zh/model-studio/fun-asr-client-events)。
