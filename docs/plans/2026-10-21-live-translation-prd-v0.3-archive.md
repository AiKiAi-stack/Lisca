# PRD：面向公开用户的直播与视频原文字幕

- 日期：2026-10-21
- 状态：v0.3；2026-10-22 用户要求优先原语言字幕，暂停界面跨语言翻译。下文历史翻译条款不再作为当前交付要求，以 ADR-0008 为准。
- 产品名称：暂沿用 stream-with-asr。
- 本文记录本轮产品讨论；现有 SPEC 与 ADR 仍记录历史需求及当前实现，本文不自动替换它们。

## 1. 产品定位与核心问题

让用户在自己的 Windows 电脑上，通过浏览器观看直播或本地视频，并获得与语音语言一致的字幕。

当前主场景为原文字幕：中文语音生成中文字幕，英文语音生成英文字幕，默认由识别模型判断语种。跨语言翻译暂时退出默认界面与验收目标；后续是否恢复另行评审。

用户不应为观看节目理解识别引擎内部状态、手动同步时间轴或编排多种工具。相较当前 demo，首版需要完成从安装、配置、开始观看到异常恢复的完整路径，并明确告诉用户哪些来源、语言和服务可用。

## 2. 已确认的产品决定

1. 面向公开发布的陌生用户，首版优先 Windows。
2. 程序在用户电脑上运行，用户通过浏览器观看。
3. 首版仅接云端 API，用户提供自己的 Key；本地模型不是首版产品交付目标。
4. 同时覆盖直播链接和本地视频文件。
5. 当前主验收方向为中文语音→中文字幕、英文语音→英文字幕。
6. 可用原文语言由识别服务的实际能力决定，不调用翻译服务。
7. 正式字幕按完整稳定短句出现，不逐词生成；按源语音时间显示终稿或重复稳定的短句。
8. 低延迟与音画字幕同步是产品目标。现有数秒或十几秒等待属于待评估的工程现状，不能直接变成产品要求。
9. 首批来源由工程侧调研和选择，用户不指定平台清单。

用户早前优先跨语言翻译；2026-10-22 根据原视频的实际错误反馈调整为原文识别优先。当前以中文原文和英文原文分别验收，翻译能力暂不作为交付要求。

当前具体显示决策与用户原视频验收见 [ADR-0008](../adr/0008-original-language-captions.md)。以下跨语言用户旅程和发布矩阵作为历史规划保留，不代表当前界面仍提供翻译。

## 3. 用户与典型任务

- 跨语言直播观众：粘贴一条可访问的直播链接，选择目标语言，边看边理解节目。
- 跨语言视频观众：选择一个本地视频，在观看过程中获得翻译字幕，并能暂停、继续与跳转。
- 有字幕辅助需求的观众：需要清晰、稳定、可调字号的字幕；同语言输出的公开承诺需另行核实服务能力。

本机运行不等于本地推理。使用前必须说明音频及必要文本将发往用户选择的云端服务，相关 API 费用由用户与服务商结算。

## 4. 首版用户旅程

### 4.1 安装与首次启动

- 提供一条文档清晰、可重复验证的 Windows 安装和启动路径。
- 首次使用能检查必要依赖，给出缺失项及明确处理方式；正常使用不要求修改源码。
- 用户可选择安装或数据存放位置，避免默认把大量媒体缓存写入系统盘。
- 启动后能打开本机浏览器页面；重复启动或端口占用有可理解的提示。

### 4.2 配置云端服务

- 用户选择受支持的服务，填写 Key 及必要配置，并进行连接检查。
- 检查失败时区分配置错误、网络不可达、认证失败和服务不可用；支持修改后重试。
- 选择源语言和目标语言。自动识别源语言仅在对应服务经过验证后提供。
- 界面展示该配置真正支持的语言组合；不支持的组合不能伪装成可用选项。
- 识别与翻译可以由同一服务或不同服务完成；所需配置、音频/文本传输对象应明确。
- Key 输入遮罩显示，不出现在 URL、普通日志或导出的诊断信息中；是否保存由用户选择，能删除已保存配置。
- 说明使用 API 会产生服务商费用；缺少可靠计费数据时不展示虚构的精确金额。

### 4.3 选择并打开内容

- 直播入口支持直接媒体地址；输入为频道播放列表时，先展示频道供用户选择。
- 平台页面链接只对已验证的平台和内容类型作支持承诺。
- 本地视频可以通过文件选择进入；不支持的封装、编码或无音轨情况应在启动云端处理前尽量提示。
- 输入错误、链接过期、来源受限和拉流失败都有明确状态及下一步动作。
- 不将直播源仓库的“收录”或“更新”声明当作本产品可播放的证明。

### 4.4 观看与翻译字幕

- 主要界面围绕视频、目标语言字幕、播放控制与必要状态组织。
- 正式字幕必须出现在视频画面内，以完整短句替换；不使用播放器下方的大段草稿框，也不逐词生成正式字幕。
- 快语速长段拆成可阅读的分页，每页有足够停留时间，不能在原语音结束时瞬间倾倒或清空整段。
- 默认只保留内容入口、翻译方向、播放器和必要控制；配置、记录、诊断、频道等按需打开。
- 对翻译语序重排的修订应限制在当前语句内，避免整屏文本跳动。
- 目标字幕默认清晰可读，字号和对比度可调；提供原文与译文同时显示的选项作为首版建议项。
- 不要求等待整段本地视频转写完毕才允许观看。
- 暂停、继续和本地视频跳转后，显示的字幕应对应当前播放位置；跳转前未完成的结果不能污染当前位置。
- 模型或网络暂时落后时，明确显示处理状态，不用无提示的长时间画面冻结掩盖处理延迟。
- 不能仅为等待完整句终稿而无条件阻塞播放；延迟预算与降级策略须以测量结果评审。

### 4.5 中断、恢复与结束

- 云端超时、限流、额度不足、直播断流分别呈现可理解的原因。
- 可恢复错误允许有限重试，并显示当前状态；永久失败不无限重试。
- 已知 API 不可用时停止继续送入新音频，提示用户处理，而不是无界积压。
- 停止或关闭会话后停止新媒体处理和新 API 请求；已发送请求可能仍由服务商计费，应如实说明。
- 新开一场内容时不混入上一场的字幕、语言配置或异步返回结果。

## 5. 首批来源选择原则与候选

本节为工程建议，来源调研见 [媒体来源调研](../research/2026-10-21-media-source-baseline.md)。候选收录不代表当前可播；本轮不进行媒体播放验证。

1. 基础必验：可访问的中文和英文直接 HLS 流，各至少一个；固定记录实际频道、语言、日期、网络条件和播放结果。
2. 频道列表必验：从公开 IPTV 列表选择频道，验证“列表→频道→实际媒体”的完整旅程，不能把频道列表直接当作一个视频播放。
3. 本地文件必验：中文与英文各一段可重复使用的视频，用于稳定测量翻译质量与延迟。
4. 平台链接候选：YouTube 与 B站代表海外与国内页面链接接入；在当前网络和选定页面通过实测前，不列入公开支持清单。
5. 其他平台：保留已有兼容能力，逐项实测后再扩大承诺，不用“所有主流平台”代替支持清单。

公开 IPTV 仓库仅作为来源发现工具；验收应固定实际频道与样本，不依赖自动更新总列表始终返回相同内容。

## 6. 完成标准与测量方法

### 6.1 必须完成的行为验收

- 新用户按说明在干净 Windows 环境中完成安装、配置 Key 和首次观看；记录过程、耗时及人工协助点。
- 中文→英文、英文→中文分别覆盖直接直播流和本地文件，形成四个独立案例，不能相互替代。
- 频道列表能完成频道选择与开始观看；候选平台页面各自保留成功或失败证据。
- 每例保存来源、语言、服务与模型版本、配置、时长、屏幕录像或截图、脱敏日志和明确结论。
- 在连续观看、网络中断、API 失败、停止重开和本地跳转时验证字幕归属与恢复行为。
- 验证未支持语言不会开始一次注定失败的会话，错误状态不会显示“翻译成功”。

### 6.2 延迟必须分开测量

- 来源固有延迟：节目现场到客户端取得内容的延迟，通常无法仅凭公共流准确测出；没有可信时间基准时标记为未知。
- 应用附加播放延迟：同一媒体时间点在可解码输入就绪与浏览器呈现之间的时间差。
- 首次字幕延迟：某个可辨认语音片段到达本机后，到首个可理解的目标语言字幕出现的时间。
- 定稿延迟：语句结束的音频到达后，到对应翻译字幕稳定的时间。
- 播放同步偏差：字幕对应语音片段在播放器时间轴上的偏差。

每项记录中位数、P95、样本量、网络和服务配置；外部平台不可测项单独说明。固定本地样本用于重复比较，公开直播用于检验真实条件下的行为。

建议先以当前版本形成基线，再验证逐步字幕方案。不得把当前 5 秒缓冲当作验收门槛，也不承诺尚无数据支持的“零延迟”。

### 6.3 发布门槛建议（待产品评审）

- 两个语言方向均通过直播和本地文件的端到端验收。
- 每个方向至少完成一次 30 分钟连续观看，记录字幕中断、卡顿、延迟增长和 API 错误；这是测试时长建议，不是已确认能力。
- 双语审阅者按预先固定的样本检查意思、否定、数字及人物关系等是否正确；单独记录识别错误与翻译错误。
- 在首轮基线后补齐延迟数值目标、翻译质量评分准则与通过阈值；门槛未定稿前不将本草案标为可直接开发或可发布。
- 安装、首次观看、可恢复错误及停止会话均有用户可见的验收证据。

## 7. 当前项目与目标之间的差距

本节保留产品草案建立时的历史基线；后续实现与显示策略以 [ADR-0007](../adr/0007-readable-on-video-translation.md) 和 [界面设计与验收记录](../ui-design.md) 为准，不能把以下历史差距视为当前状态。

- 当前 WebUI 已有媒体输入、识别引擎、播放器、字幕样式及局域网分享基础；这不等于跨语言翻译已接通。
- 尚需验证并建立“识别→翻译→当前语句修订→字幕定稿→播放位置关联”的完整用户体验。
- 现有 SPEC 更偏早期中文字幕和引擎里程碑，README 更偏流媒体处理工具包；公开发布前需统一产品定位。
- 当前 ADR-0004 记录以字幕就绪程度限制播放进度的机制。允许逐步翻译与低延迟目标可能需要调整该设计；实现前应以实验数据更新决策记录，而不是仅改旧测试的期望值。
- 云端 API 的源语言、目标语言、流式输出、句末标记、时间戳、限流和费用能力尚需逐项核实。
- 本轮没有证明当前版本达到延迟、翻译质量或干净环境安装要求。

## 8. 首版范围边界建议

本节是控制交付规模的建议，不改变已确认的用户决定。

- 首版集中完成单机、单场观看；不新增托管网站、多用户账号、订阅收费或公网分享。
- 已有局域网分享保留，但新增分享能力不作为首版翻译体验的前提。
- 本地模型、多平台安装支持、配音、批量翻译、字幕编辑器与字幕导出增强列为后续候选。
- 不以支持大量服务商替代完整体验；先验证至少一组满足两种翻译方向的云端服务配置，再扩展适配。

## 9. 分阶段交付建议

1. 能力验证：确定云端服务配置和语言能力，使用固定本地中英文样本测出识别、翻译与时间对齐基线。
2. 最小完整体验：本地文件从配置到观看走通，两种翻译方向、逐步字幕及暂停跳转可用。
3. 直播接入：完成直接流和频道列表旅程，并用真实直播测量长时间稳定性；平台页面逐个验收。
4. 公开发布准备：完成 Windows 安装路径、错误恢复、Key 管理、支持清单和一致的用户文档。

以上是交付顺序建议，不意味着首版删除直播或任一翻译方向。

## 10. 草案审阅与实施前需收敛的事项

- 确认本文是否准确表达首版定位、范围及建议边界。
- 云端服务配置及支持语言：由工程调研和能力实验给出建议；涉及用户付费或使用真实 Key 前遵循实际授权范围。
- 延迟、质量阈值及异常时的播放降级策略：以基线结果形成可评审方案。
- Windows 安装方式：在干净环境验证后选定；不把当前开发者环境作为陌生用户的使用前提。
- 用户确认共同理解后，再按仓库约定把开发规格与任务发布到 GitHub Issues，并与现有 SPEC、ADR 建立明确关系。

产品草案之后已进入实现与真实云端验收。当前功能与本机证据见 ADR-0007 和界面设计记录；干净 Windows 安装、完整来源矩阵、长时间稳定性及发布指标仍需验证。
