## Problem Statement

观看者需要在自己的 Windows 电脑上打开视频或直播，看到与当前语音对应的原文字幕，并且能放心暂停、跳转、停止与处理故障。现有链路已经能识别并显示中英文，但完整观看体验、控制后的请求数量、异常等待和发布证据尚未闭环。测试通过、API 返回文字或文档定稿，均不能单独证明用户可以顺利完成观看。

本规格承接已有 PRD，将剩余工作组织为可独立验证的交付切片；产品目标和首版范围不变。

## Solution

复用当前浏览器播放器、云端识别会话和原文字幕时间轴，补齐从配置、打开内容、出现短句、控制播放到故障退出的完整路径。以当前媒体位置决定画面字幕，以会话归属隔离异步结果，以明确的等待和恢复预算限制计费处理。

交付分为自动化行为验证、真实媒体与识别质量验证、干净 Windows 和第二台设备验证。每类证据单独记账；外部条件缺失时保持“受阻”，不降低 PRD 门槛来换取通过。

## User Stories

1. 作为首次使用者，我希望按说明在 Windows 启动页面，以便无需修改源码就能开始观看。
2. 作为首次使用者，我希望缺少依赖、安装失败或端口占用时看到下一步操作，以便自行恢复。
3. 作为观看者，我希望在设置中填写遮罩显示的 Key，并了解音频发送方与费用承担方，以便知情使用识别服务。
4. 作为观看者，我希望 Key 默认只在本次运行有效，并可选择加密保存和删除，以便控制本机凭据留存。
5. 作为观看者，我希望连接检查如实说明验证到了哪一步，以便不会把发起连接误当作识别成功。
6. 作为观看者，我希望通过文件选择或本机路径打开视频，以便直接观看已有内容。
7. 作为观看者，我希望无法解码或没有音轨的内容在识别前被拒绝，以便避免无意义的计费请求。
8. 作为观看者，我希望直接直播流和频道列表各自有正确入口，以便打开所选节目。
9. 作为观看者，我希望知道失败发生在列表读取、页面解析还是媒体拉流，以便采取对应操作。
10. 作为中文或英文观众，我希望默认保持语音原语言，以便没有隐式翻译或额外翻译费用。
11. 作为观看者，我希望视频内显示完整稳定短句，草稿留在记录区，以便字幕可读而不逐词跳动。
12. 作为观看者，我希望长句按语音和语义拆分，已撤回文字不复现，以便理解当前内容。
13. 作为观看者，我希望字幕遵循媒体时间，迟到内容只留记录，以便旧台词不会覆盖后续语音。
14. 作为本地视频观看者，我希望收到覆盖当前位置的字幕后即可播放，以便不必等待整个长文件识别完成。
15. 作为本地视频观看者，我希望识别完成后的暂停、继续和任意跳转复用现有字幕，以便不重复付费。
16. 作为本地视频观看者，我希望跳到尚未准备的位置前获知可能再次调用 API，并停止旧位置处理，以便控制费用并避免字幕串位。
17. 作为本地视频观看者，我希望长暂停后从恢复位置继续，以便无需无提示地重跑整段文件。
18. 作为观看者，我希望静音内容可以播放并显示无语音状态，以便不会一直等待首条字幕或看到猜测的台词。
19. 作为本地视频观看者，我希望识别连续无进展 15 秒后能重试、仅播放或停止，以便不会无限等待。
20. 作为直播观看者，我希望同一次字幕故障累计等待不超过 2 秒，随后继续媒体并提示字幕缺失，以便直播不会反复冻结。
21. 作为直播观看者，我希望恢复和重连后字幕重新对应当前节目位置，以便不会倒放旧文字。
22. 作为观看者，我希望自动恢复最多尝试 2 次，且能看到次数和等待，以便故障不会无限重试。
23. 作为观看者，我希望停止、仅播放、切换内容或删除配置后没有新识别请求，以便控制后续费用。
24. 作为观看者，我希望字号、位置、对比度、全屏和窄屏都能正常使用，以便看清字幕且不挡住播放操作。
25. 作为局域网观众，我希望加入主机同一场原文字幕直播，以便共享现有识别结果而不另开付费会话。
26. 作为用户，我希望找到并清理媒体副本、日志和配置，以便管理本机数据。
27. 作为发布维护者，我希望质量报告绑定正确输入，并区分转写、画面、同步和流式延迟，以便不会发布未经证明的能力。
28. 作为新用户，我希望公开支持清单只包含实际验证的格式和来源，以便能够判断自己的内容是否适用。

## Implementation Decisions

### 会话与时间轴

- 继续使用现有 HTTP 会话创建、WebSocket 识别事件和浏览器播放器控制接口；优先在当前边界补行为，不先建设新的通用框架。
- 主机会话负责输入、识别服务和取消信号；浏览器负责当前媒体位置与显示。解码时间映射到播放器媒体时间后，字幕统一使用这一时间轴。
- 每次换源、停止重开或需要重建识别的跳转推进会话代次。WebSocket、媒体错误、解码时钟和异步解析结果均检查所属代次；句子 ID 只在所属会话内有意义。
- 字幕控制按“准备中、播放中、用户暂停、字幕等待、降级、仅播放、停止、完成、错误”表达外部状态。识别传输结束不能单独当作内容处理成功；取消、失败和正常结束在记录中可区分。

### 原文字幕与本地控制

- 默认会话和连接检查仅使用识别器。画面采用稳定短句或终稿；记录保留可修订草稿与完整识别内容。旧显式翻译调用保留既有兼容边界。
- 原文短句由语音时间、词时间与语义边界共同确定；正常前进时不逐词改写，不套用历史翻译阅读队列，也不把过期字幕顺延到后续语音。
- 同一会话内已完成的本地字幕索引独立于识别连接存活；播放器控制不能因连接关闭而丢掉已经完成的结果。
- 未完成时跳到已准备区间复用字幕；跳到区间外先提示可能重建识别，从新位置处理并取消旧位置工作。短暂停顿优先复用连接，失效或长暂停后按恢复位置重建。
- 本地音频投送继续使用实际 PCM 时长与有界提前量；当前实现的 2 秒提前量是投送节奏限制，不是固定附加播放延迟或公开性能承诺。暂停不能累计出恢复后的突发投送额度。
- 本地结束后不再发送新音频，画面清空已过期字幕，已有索引仍可供本次会话内回看。

### 等待、恢复与资源

- 本地准备与等待采用 15 秒无真实进展预算；字幕范围或确认处理范围前进才算识别进展。用户暂停、重复状态、发送音频与心跳不得伪装成新识别进展。经输入和连接状态确认的静音分开处理。
- 直播字幕故障累计等待最多 2 秒，随后保持媒体前进并持续提示缺失。迟到事件不能重置预算；只有已追上当前媒体并持续推进，或用户显式重新启动，才结束该次故障。测试必须包含一串迟到结果，而不只测试一个超时。
- 可重试的临时故障由会话控制统一约束，媒体与识别层不能各自隐式叠加重试。每次故障最多 2 次恢复；已知认证/权限/额度问题等待用户操作，不自动重试。临时错误的已确认初始退避为 1 秒、2 秒，作为可观察工程参数，停止可立即取消等待。
- 来源断流、识别故障和无可辨认语音使用不同状态。服务商未给出原因时保持未知，不能把限流与额度不足强行判成其中一种。
- 停止、仅播放、配置删除、拥有者断开和内容切换共用取消路径，阻止新音频、新任务和重试；已经发出的请求不能撤销服务商计费。测试统计动作前后的请求与投送，而不以 UI 按钮变化代替停止证明。
- 媒体缓冲、草稿、待处理事件与后台任务必须有容量边界及清理路径。可合并过时草稿，不能默默丢掉终稿而仍宣称完整记录；本地会话保留完整字幕的方式必须支持完成后的任意跳转。长文件验证同时记录容量策略、峰值和结束后的释放情况。

### 输入、隐私与共享

- 在创建识别器前完成能在本机确认的可打开性、音轨和浏览器可播性检查。运行中出现媒体失败时停止对应识别工作；不得为了试听来源默默启动收费识别。
- 格式/编码、直接流、频道列表和平台解析分别保留结论。具体平台页仍按 PRD 的扩展案例处理，未实测条目不进入公开支持清单。
- 默认 Key 只在服务内存保存；可选保存采用已有 Windows 用户绑定加密。配置删除与媒体/日志清理是不同操作，说明和诊断不得暴露 Key、会话凭证或敏感 URL 参数。
- 观众复用主机会话，只接收所需媒体和字幕数据；不能读取配置或创建独立识别。保留最多 3 台观众以及停止即失效的边界。

### 证据与发布

- 固定本地参考集与录音分别记录实际输入身份，评分前核对 SHA-256。参考集声明的哈希与识别输入的哈希分别表达；错配或旧录音缺少来源证明不能变成已核验来源。
- 直播按来源、语言、日期、环境和采样区间留证，不用可变化 URL 充当不可变内容哈希。测试替身只证明控制逻辑，真实服务与真实播放器各自提供对应证据。
- 继续使用 PRD 的 A01–A10 和质量阈值，不因本次规格成文、回归通过或临时环境受阻更改门槛。每项记录未执行/通过/失败/受阻，并给出证据、适用范围和未解决问题。
- 中英文准确率、至少 50 个短句的同步偏差与覆盖、各至少 20 次独立实时启动、各 30 分钟直播、快语速、长本地文件、干净 Windows 和第二设备分别验收。量化方法和数值以 PRD 第 7 节为准。

## Testing Decisions

### 已确认的测试边界

1. **主要边界：公开 HTTP/WebSocket 会话到真实浏览器播放器。** 从用户配置、打开、暂停、跳转、仅播放、停止操作出发，断言画面字幕、媒体时间、状态和外部请求计数。识别服务和来源可用可控替身，播放器与会话路由保留真实实现。
2. **评分边界：录音与固定参考集输入到评分报告。** 验证输入匹配、归一化、修订/撤回、错误/结束和隐式翻译检查；不以内部编辑距离循环的实现细节充当整个评分链路证明。
3. **平台边界：干净 Windows 启动与第二台设备加入。** 用户绑定加密、实际安装、浏览器支持及第二设备观看须在相应环境留证，Linux 回归不能代替。

已有 HTTP/WS 测试已能替换媒体源和识别器，前端已有短句与等待状态回归，评分已有文件输入，因而优先扩展这些入口。只有现有入口不能驱动时间或故障时，才引入最小的时钟/服务适配，不为测试新建一整套产品架构。

### 自动与真实验证的分工

- 自动验证覆盖：不隐式翻译、错误输入不启动识别、完成字幕复用、跨代次隔离、静音、无进展、混合媒体/识别故障预算、停止后的新请求为零及共享权限。
- 浏览器验证覆盖：字幕实际可见与消失、媒体时间、暂停/跳转、两行与裁切、全屏/窄屏，以及可操作状态。Node 中的函数回归作为快速反馈，不能替代真实播放器验证。
- 真实识别只在具备用户授权和所需配置时进行，有明确样本和运行上限；故障注入优先离线完成。历史日志可作调查线索，不自动升级为本轮通过证据。
- 长文件必须在整段识别完成前开始播放，并检查未准备区间跳转、连续取消及资源释放；不能用很快处理完的短片冒充该案例。
- 以行为回归和可重复测量判断完成，不镜像内部函数实现，不用截图存在、WebSocket 返回文本或 HTTP 200 单独判定观看成功。

## Out of Scope

跨语言翻译入口、双语字幕、跨刷新持久字幕产品、音轨转码、额外本地模型产品化、macOS/Linux 安装产品化、账号/收费/托管平台、公网分享以及新平台支持承诺。以上继续遵循 PRD 的范围边界；测试用临时证据存储不构成持久字幕产品。
