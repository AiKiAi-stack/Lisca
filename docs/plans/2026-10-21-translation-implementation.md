# 云端翻译字幕：实现与验收记录

日期：2026-10-21（Asia/Shanghai）。对应 [已批准 PRD](2026-10-21-live-translation-prd.md)。

## 本次交付

- Windows 启动脚本、项目内环境与依赖检查；安装缓存优先保存在项目所在盘。
- 本机浏览器填写百炼 Key、连接检查、可选 Windows DPAPI 加密保存与删除。真实验收的用户 Key 仅放入服务内存。
- 显式中→英、英→中方向；FunASR 使用对应源语言提示，Qwen-MT Flash 使用明确的源/目标语言参数。
- 有界、按语句合并的识别草稿队列与流式翻译；终稿不被旧草稿覆盖。错误、限流、截断、超时均可见。
- 翻译草稿与迟到译文在明确标注的区域显示；有已确认时间范围且未迟到的字幕可以按播放位置叠加。没有将旧句移到后续画面上伪装同步。
- 新云端模式不等待整句终稿来冻结音视频；暂停、继续、本地 seek、停止及会话隔离接入原有播放器。
- 停止会阻止新任务、清空排队任务并关闭翻译响应；已开始的请求允许有限收尾，不能撤销服务商已产生的费用。
- M3U/M3U8 频道列表与单路 HLS 区分；YouTube、B站等页面通过现有解析器接入，未实测的平台不进入已验证支持清单。
- 旧命令行与原有局域网分享路径保留。

## 自动验证

- 本机完整 pytest：110 项通过；包含原有媒体解析、字幕同步、ASR 和局域网分享回归。
- 新增测试覆盖：配置脱敏、受支持语向、逐步翻译、SSE 增量、HTTP 错误、截断、跨站拒绝、DPAPI 往返与删除、停止并发、过期会话及精确本地音频跳转。
- 与 CI 相同的 Pylint errors-only 检查通过。
- Windows 启动依赖检查通过，缺失的 yt-dlp 已安装到 D 盘项目环境。未把当前机器的检查等同于干净 Windows 安装验收。
- Standards 与 Spec 两轴审查后修复了 PATH、连接检查误报、草稿时序、停止竞态、Key 更新语义和分享生命周期问题。

## 真实 API 短样本

用户明确提供 Key 用于本次短样本验收；没有将 Key 加入样本、代码、日志或报告。

样本由本机 Windows TTS 合成，分别使用 Microsoft Huihui Desktop 和 Microsoft Zira Desktop，包装为 H.264/AAC 视频。所有本机原始记录位于 `logs/translation-acceptance/`；该目录不随代码提交。

### L1：中文本地视频 → 英文

- 输入：`zh.mp4`，约 11.44 秒。
- SHA-256：`5f7339b7d9ec8af6234b25e4d55921261b3317637d028117c9431364fe2de4c5`。
- 原文：欢迎使用实时翻译。今天是星期三。下一班火车将在下午三点到站。请不要关闭窗口。
- 输出：4 句翻译终稿；包括 “The next train will arrive at 3:00 p.m.” 和 “Please do not close the window.”，数字与否定含义保留。
- 首个流式译文事件：连接后约 2125ms；没有 API 错误事件。
- 证据：`zh-to-en.json`，包含原文、译文、句子编号、源时间范围和接收时间。
- 判定：固定短样本端到端通过。该数字不是对所有内容的延迟承诺，也不是完整句翻译时延。

### L2：英文本地视频 → 中文

- 输入：`en.mp4`，约 10.17 秒。
- SHA-256：`da161ab52a7990f0ede3314ce538570cc43d7179698d6aa494b5aa586cdf0543`。
- 原文包含 “The next train will arrive at three in the afternoon.” 和 “Please do not close the window.”。
- 输出：4 句终稿，包括“下一班列车将于下午三点到达。”和“请不要关闭窗口。”。
- 首个流式译文事件：连接后约 1719ms；没有 API 错误事件。
- 证据：`en-to-zh.json`、`en-to-zh-browser.png`。
- 浏览器观察：视频推进到结束，双语内容与历史可见。部分终稿比对应声音晚约 1–2 秒，已显示迟到提示；未达到严格同步。
- 另在浏览器验证暂停后进度保持、继续播放及 seek 重新建立会话。精确跳转位置另由真实解码测试断言。

## 公共 HLS 冒烟

以下分别保留案例，不能用成功来源替换失败结果。公开清单只用于发现候选，来源依据见 [iptv-org 中国清单](https://raw.githubusercontent.com/iptv-org/iptv/master/streams/cn.m3u) 和 [best-fan 央视清单](https://raw.githubusercontent.com/best-fan/iptv-sources/main/cn_cctv.m3u8)。

### H1：中文来源，失败

- 输入：`https://liveplay-srs.voc.com.cn/hls/tv/134_180adf.m3u8`。
- 上限 20 秒；约 17.6 秒时媒体读取失败，没有译文。
- 证据：`live-zh-en.json`。
- 判定：当前网络条件下未通过，不列为可用来源。

### H2：另一中文候选，未通过

- 输入：`https://event.pull.hebtv.com/jishi/cp1.m3u8`。
- 上限 20 秒，窗口内没有生成译文。
- 证据：`live-zh-en-hebtv.json`。
- 判定：未通过；没有错误事件不等于播放或翻译成功。

### H3：CGTN 英文来源，部分通过

- 输入：`https://english-livebkali.cgtn.com/live/encgtn.m3u8`，来自 iptv-org 中国清单中的 CGTN 条目。
- 20 秒 API 冒烟收到 159 个流式译文事件，首个约 4109ms，其中约 3 秒用于来源初始化；连续语音在该窗口内未形成终稿。
- 此外实际浏览器观察到 1920×1080 视频、播放进度持续推进、音轨未静音，以及持续出现的双语文本。已人工点击停止，未让云端调用无限持续。
- 证据：`live-en-zh.json`、`live-en-zh-browser.png`。
- 判定：拉流、浏览器视频与逐步翻译链路通过短时观察；字幕草稿较长、同步与翻译质量没有因此视为达标。未验证物理扬声器出声、其他设备或 30 分钟稳定性。
