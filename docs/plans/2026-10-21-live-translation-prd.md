# PRD：面向公开用户的直播与视频原文字幕

- 版本：v1.0 需求基线，更新于 2026-10-22；创建于 2026-10-21。
- 产品：stream-with-asr，Windows 本机运行、浏览器观看、用户自带云端识别 API Key。
- 文档状态：正文已统一为原文字幕，可据此拆分开发与验收工作；产品尚未完成发布验收。
- 决策来源：用户本轮确认与 [ADR-0008](../adr/0008-original-language-captions.md)。下文的异常等待上限和数值指标是本轮提出的工程验收目标，尚待实现或实测，不代表用户此前指定的数值或已达到的能力。
- 阅读方式：第 1–6 节定义目标行为，第 7 节定义验收方法，第 8 节记录证据与缺口。需求写入文档、代码实现、验收通过、允许发布分别记录。

## 1. 产品目标与用户

让陌生用户在自己的 Windows 电脑上打开直播或本地视频，看到与正在播放的语音相对应、清晰可读的原文字幕。中文语音显示中文，英文语音显示英文；默认自动判断语种。

主要用户是需要字幕辅助听清节目内容、核对快速口播或在不便开声音时观看内容的观众。首次使用者应能按说明完成安装、配置与第一次观看，无需修改源码、选择内部引擎或手动校准时间轴。

核心成功结果是“当前声音与当前字幕对应”。字幕内容、出现位置和显示时机都正确，才算完成观看链路；API 返回成功或生成一份完整转写不能单独证明观看体验合格。

## 2. 首版范围

### 2.1 已确认的范围

- 面向公开发布的陌生用户，首版优先 Windows；程序在用户电脑运行，以本机浏览器作为观看界面。
- 仅使用云端识别，用户自行提供 Key 并承担服务商费用。当前适配以已有百炼 FunASR 为基础。
- 直播链接与本地视频都在首版范围内。直接媒体流、频道列表、平台页面是三种不同输入，分别验收。
- 原文字幕优先验收中文、英文；其他语种只有完成独立验证后才能进入公开支持清单。自动识别不等于承诺所有语言或任意混合语音均准确。
- 正式字幕在视频内以完整稳定短句出现，不以逐词更新的草稿作为主画面。
- 低延迟和音画字幕同步是目标。固定延迟数秒或十几秒不是产品要求；实际识别等待、媒体缓冲和播放同步偏差分别测量。

### 2.2 范围外与兼容边界

- 当前观看界面不提供跨语言翻译、目标语言选择或双语字幕。恢复这些能力需要新的需求和独立验收。
- 旧翻译 API 的显式调用兼容性按 ADR-0008 保留；默认会话、页面和连接检查只使用识别服务。
- 本地模型、macOS/Linux 安装产品化、系统声卡采集、配音、批量处理、字幕编辑器和字幕导出增强不进入本轮必交付范围。测试中生成 SRT 不等于已经提供产品导出功能。
- 首版集中于单机、单场观看，不新增账号、订阅收费、托管平台或公网分享。已有局域网分享能力保留，其旧有测试不能替代原文字幕模式的兼容验证。

## 3. 完整用户旅程与功能要求

以下 R 编号是稳定的需求标识，后续开发任务与验收记录引用这些编号；当前落实状态见第 8 节。

### R01 安装与启动

- 提供一条明确的 Windows 安装路径，说明支持的系统、浏览器、Python/依赖前提和网络要求。当前启动入口为 `start-windows.cmd`，首次启动安装项目依赖并打开本机页面。
- 安装目录和媒体数据允许放在非系统盘；界面或说明明确上传副本、缓存和日志的位置及清理方法。
- 缺少依赖、首次安装失败、端口占用、重复启动分别给出下一步操作，用户无需编辑源码。
- 以干净 Windows 环境的实际安装记录确定公开支持版本，开发者机器可启动只记为局部验证。

### R02 配置云端识别与保护 Key

- 首次使用从“设置”填写 Key，说明音频发往哪个服务、账户费用由谁承担，再由用户启动识别。
- 默认仅本次运行有效；可选本机加密保存，并能删除保存配置。输入遮罩显示，Key 不出现在 URL、普通日志、浏览器持久存储或诊断导出中。
- “检查连接”只检查识别服务。结果区分“已发起连接”和“真实音频识别成功”，不把前者显示成完整能力验证。
- 认证失败、额度不足、限流、网络错误与未知错误尽量分别提示；服务商未提供原因时如实显示未知，不编造错误类别或费用。

### R03 选择与打开内容

- 默认页面保留内容输入、打开文件、生成/停止字幕、播放器与必要状态；设置、字幕记录、频道和诊断按需打开。
- 本地文件支持文件选择与本机路径。处理前检查可打开性和音轨；无法解码或没有音轨时明确提示，避免无意义的计费请求。
- 直接直播地址打开媒体；频道播放列表先显示频道供选择；平台页面先解析为媒体。失败信息应能区分列表读取、页面解析和媒体拉流阶段。
- 公共支持清单写明已验证的地址类型、平台/频道、验证日期和限制。来源仓库收录某条地址只作为候选证据。

### R04 原文语言行为

- 默认自动识别，中英文分别保持原语言文字。高级设置可提示中文或英文；观看入口不要求选择目标语言。
- 当前界面、默认会话和连接检查均不创建翻译请求，旧客户端仅发送源/目标语言参数也不应隐式启用翻译。
- 未验证语种只作为能力探索；未识别到语音、服务不支持语种和识别连接失败应分别呈现，不能用猜测的语言状态伪装成功。
- 中英混说、方言、多人重叠和强背景音单独评估，不用清晰单人样本的结果覆盖这些场景。

### R05 字幕显示与可读性

- 原文字幕叠加在视频内，全屏仍可见；字号、位置和对比度可调整，字幕开关不遮挡播放控制。
- 草稿可在字幕记录修订；画面使用稳定短句或终稿，整体替换当前短句，避免逐词跳动。撤回或修正不能让已废弃文本重新出现。
- 长段按照语义、标点及语音时间拆分为短句，常规桌面视口以最多两行为验收目标；窄屏换行后仍须可读。不能把整段文字在结束时集中倾倒、裁切成看不见的内容或连续闪烁。
- 源语音时间优先于人为阅读队列。快语速时在对应语音区间内合理合并/拆分；不能为让旧字幕停留而持续覆盖后续无关语音。完整识别内容保留在记录中供回看。
- 正常时间轴前进时，终稿不逐词改写；纠正采用完整短句替换，过期结果按 R06 处理。

### R06 播放与字幕同步

- 按播放器媒体时间关联字幕，音画共同前进；字幕显示与识别回调到达顺序解耦。
- 本地文件可以提前处理音频，收到覆盖当前播放位置的可用字幕后播放，不强制等待整个长文件完成。初始等待有状态、取消入口和无进展处理。
- 已过显示区间的迟到字幕保留在记录，不排到后续画面。暂停时维持当前媒体时间及对应字幕；恢复时继续按同一时间轴显示。
- 连续缓冲、跳转、切换文件、停止重开后均按当前会话和媒体位置过滤结果；上一会话或旧跳转位置的异步返回不能污染画面。
- 等待上限与故障降级见第 4 节；上限是故障等待预算，不是固定附加播放延迟。

### R07 本地暂停、跳转与结束

- 同一次会话内，已完成原文识别的本地视频暂停、继续和任意跳转复用已有字幕，不重新发起识别请求。
- 识别未完成时，跳转到已准备好的范围直接显示；范围外从新位置准备字幕，提示可能重新调用 API，停止旧位置继续处理并过滤旧结果。
- 短暂停顿尽量复用仍有效的识别连接；连接已失效或长暂停需要重建时，从恢复位置继续，避免无提示地重跑整段文件。
- 文件播放结束清空已结束的画面字幕；生成任务已完成后不因停留在结尾持续请求 API。切换内容重新建立独立时间轴。
- 首版只承诺会话内复用，跨刷新、重启的持久字幕缓存不作为既有能力。

### R08 直播观看

- 首批必验中、英文直接 HLS 流，各至少一条；频道列表另验“选择频道→解析媒体→播放与字幕”。平台页作为候选，逐项实测后再列入支持清单。
- 媒体正常而识别落后时按第 4 节有界等待并显式降级；媒体断流则显示断流，不能用字幕等待状态掩盖来源故障。
- 恢复字幕后只显示与当前媒体位置对应的短句，不倒带旧文本、不高速清空历史队列；直播重新连接后的时间轴需要重新关联。

### R09 错误恢复、停止与资源边界

- 无效 Key、权限/额度错误直接等待用户修改或重试；网络与临时服务错误按有界策略处理，不能无限自动重试或持续消耗费用。
- 同一次故障的自动恢复总共最多 2 次，间隔与当前次数可观察；仍失败进入可操作的错误状态，不能因连接再次失败就重置计数。这个次数为本轮工程目标，尚未证明当前版本全部落实。
- 停止、新开内容、删除配置或关闭拥有者会话后停止新音频投送和新 API 请求，释放该会话资源；已经发送的请求可能仍由服务商计费。
- 媒体缓存、字幕积压和后台任务应有边界与停止路径。不得靠无限积压维持界面显示“识别中”。

## 4. 可观察状态与降级规则

这些是目标行为。与现有实现的差异作为待实现项记录，不因为文档写出规则就标记完成。

- **未配置/可开始**：显示配置或内容入口；未完成必要配置时解释原因，不创建付费会话。
- **准备中**：显示“正在读取音频/准备原文字幕”；播放器尚未自动开始时允许取消或选择“仅播放”。与本地字幕等待共用 15 秒无进展规则；可用字幕范围推进或服务确认已处理的音频范围推进才算识别进展，持续发送音频、心跳和重复状态不算进展，不伪造完成百分比。
- **播放中**：仅显示当前短句，记录区可以更新草稿；“字幕关闭”只隐藏字幕，停止识别需使用明确的停止入口。
- **用户暂停**：媒体时间和画面字幕保持；已准备完的本地字幕可以直接继续。识别连接的维持与重连按 R07 执行。
- **本地字幕等待**：已知下一个语音区间未准备好时，允许在边界暂停并说明原因。有新可用结果后恢复；连续 15 秒没有字幕/处理进展则停止新音频投送，提供“重试”“仅播放”“停止”，不自动重复付费请求。
- **直播字幕等待**：来源可播而字幕落后时，同一次故障为字幕等待累计最多 2 秒；到上限继续媒体播放，明确显示“字幕暂不可用/部分缺失”，过期结果留记录。降级期间保持媒体前进，不能每收到一条迟到结果就再次暂停；只有字幕已追上当前媒体位置并可持续显示，或用户显式重新启动，才结束该次故障。恢复后对齐当前内容，不补播旧字幕。来源自身缓冲另记，不计作这 2 秒规则已通过。
- **静音/无可辨认语音**：确认媒体有音轨且输入在推进时，显示“暂未识别到语音”，不猜测台词；静音媒体可以继续播放，不能无限阻塞在首条字幕。静音与 ASR 故障需用输入和连接状态区分。
- **错误/停止/完成**：显示原因与可行下一步；停止新处理。选择“仅播放”后不继续后台识别或保留会恢复计费的隐式重试；字幕暂不可用须始终可见，直到重新显式启动字幕。

15 秒与 2 秒是有待实现和验证的故障预算，可在记录原因与实测后调整；它们不要求正常播放额外等待这些时间。对于本地已经结束的语音，也不能把迟到字幕补到后续无关画面。

## 5. 输入、安装与数据边界

- **本地视频**：先固定 MP4 常见音视频编码样本，再扩大封装/编码支持；浏览器与解码器均通过后才能公开承诺相应格式。记录大文件的准备耗时、内存、磁盘副本与取消行为。
- **直接直播与频道列表**：来源由工程侧选取、试听确认中英文并固定具体案例；参考 [来源调研](../research/2026-10-21-media-source-baseline.md) 仅作发现入口，不能当作本轮播放证明。
- **平台页面**：YouTube、B站是历史候选；地域、账号、请求头与网络限制逐项记录。某一平台页通过不能外推该平台所有内容可用。
- **安装**：发布前至少在一套干净 Windows 目标环境和公开声明的浏览器版本走通，记录具体版本。其他系统/浏览器尚未验证就明确标注。
- **数据**：用户能找到并清理本机媒体副本、日志和保存配置；删除配置与删除媒体分别说明。诊断只保留必要信息，移除 Key、会话凭证及源 URL 中的敏感参数；诊断默认留在本机，不自动上传媒体文件或收集遥测。为云端识别发送音频的行为按 R02 单独告知。

## 6. 需求优先级与完成定义

- **P0：首次成功观看**——R01–R07 与 R09，中文和英文原文、本地打开、字幕可见、时间正确、可暂停/跳转、可停止、Key 处理和错误恢复。直播基础 R08 同属首版必交付，不能因先实现本地而从发布范围删除。
- **P1：来源扩展与使用完善**——频道列表流程、公开支持清单、窄屏布局和现有局域网观众兼容验证。必验频道列表在首版发布前仍须通过；优先级只表示实施顺序。
- **后续候选**——跨语言翻译与第 2.2 节扩展。历史能力不自动升级成首版完成项。

“已实现”须有对应代码；“已验证”须有与当前原文模式匹配的测试与用户可见证据；“可发布”须满足第 7 节全部必验项。单个短视频成功、自动化测试全绿或文档定稿都不能单独替代发布验收。

## 7. 验收案例、测量与初始工程目标

### 7.1 必验案例

每例独立记录输入、实际输出与结论，状态取未执行/通过/失败/受阻。保留失败证据；更换来源必须建立新案例。

1. **A01 中文本地视频**：保留用户原文件 `uploads/output.mp4` 作为回归样本；检查约 5.1 秒“别太装”、约 23.8 秒“我们还是很期待的”与当前画面/语音对应，再审阅全片而非只看两个点。
2. **A02 英文本地视频**：固定英文语音视频，核对英文原文、拼写空格与音频时间；英文 API 返回文本只能证明识别路径，播放器也要独立留证。
3. **A03 中文直接直播**：试听并记录具体媒体地址、来源、日期、网络与中文语音；连续 30 分钟，覆盖字幕落后/恢复并检查延迟是否增长。
4. **A04 英文直接直播**：另选确认有英文语音的直接流，独立连续观看 30 分钟，保留与 A03 同样的输入、时间测量和异常证据；中文直播通过不能替代此项。
5. **A05 频道列表**：从列表选择频道后实际播放，确认频道归属、字幕语言和失败提示；列表成功加载不是播放通过。
6. **A06 快语速与长句**：中英文分别覆盖连续口播、短停顿和超长识别段；全程无结束时集中倾倒、旧字幕覆盖后续内容或调度导致的连续闪现。
7. **A07 控制与会话隔离**：暂停 3 秒和 30 秒、前后跳转、连续跳转、停止重开与切换文件。验证字幕位置、旧事件隔离及识别完成后复用时新增识别请求为 0；未完成时的重新调用按 R07 提示。另用至少 30 分钟本地视频验证提前播放、未准备区间跳转、资源边界和取消，不能只用整段很快识别完成的短片替代。
8. **A08 边界与故障**：无音轨、纯静音、错误/受限来源、无效 Key、额度/限流、网络中断、识别超时。逐一核对第 4 节状态、恢复次数、停止处理和“仅播放”行为。
9. **A09 新用户安装与隐私**：干净 Windows 上从启动到首次中英文观看；检查默认仅内存 Key、可选加密保存/删除、日志脱敏、数据位置与端口占用提示。
10. **A10 界面与既有兼容**：默认布局、设置/记录收起、字幕开关、字号/位置、全屏、窄屏，以及局域网观众的原文字幕归属。不同终端保留各自证据。

平台页面作为扩展案例逐项记录；只有对应案例通过才进入平台支持清单。

### 7.2 证据与测量方法

- 本地输入记录文件 SHA-256、时长、音轨、片段与人工参考文本；直播记录频道、实际语音语言、输入地址和测试环境。对外报告脱敏 URL，私有复现资料按本机数据管理。
- 中文以字符错误率 CER、英文以词错误率 WER 核对终稿。移除标点、统一大小写与空白后计算替换/删除/插入数除以参考长度；数字写法等归一化规则在测试前固定，不能为通过而事后改规则。
- 人工标注语音起止点，与屏幕录像中的字幕可见时刻及媒体时间比较；字幕事件已经返回不等于已经呈现。分别统计起始与消失偏差的绝对值、P50、P95、最大值和样本量。
- 分开记录：点击开始到可播放的准备时间、音频到达本机到首条稳定短句可见的首次字幕延迟、句末到终稿可见的定稿延迟、应用附加播放延迟、字幕与当前语音的同步偏差。
- 流式延迟使用实时节奏输入；本地提前识别可以把字幕预先准备好，不能用它宣称直播实时延迟达标。来源固有延迟无可信基准时记未知。
- 同步记录缓冲/暂停时长与次数、字幕缺失区间、请求数量、资源增长及错误。不能只统计已显示的字幕而漏掉整段无字幕或冻结时间。

### 7.3 初始工程验收目标

以下是可测的首轮工程目标，尚未测得达标，不作为对外性能承诺。测试前固定样本与环境，达不到则记录缺口；目标调整需要说明原因，不能将当前实现结果直接写成门槛。

- **原文与隔离**：A01–A10 对应路径中的隐式翻译请求为 0；已完成本地识别后的暂停/跳转新增识别请求为 0；停止或会话切换后的旧字幕污染为 0。
- **识别正确性**：清晰单人语音，中英文各至少 5 分钟独立参考集；中文 CER ≤10%，英文 WER ≤15%，分语言单独通过。快语速各加至少 1 分钟测试，单独报告；关键否定、数字与人物指代错误逐条复核，不能仅靠平均分掩盖严重误义。
- **字幕同步**：每种语言至少 50 个短句，起始/消失偏差绝对值分别达到 P95 ≤0.5 秒、最大值 ≤1 秒。正常有声片段字幕覆盖 ≥95%，按参考语音区间内有对应字幕的时长除以全部参考语音时长计算；缺失与过期未显示区间记为缺口，不能靠不显示字幕改善同步统计。**2026-11-04 决定：门槛不变；当前状态 unknown，不能记通过。PR89 预览合入不以此项为阻塞，正式发布仍必须通过（见 §11）。**
- **流式可用性**：每种语言至少 20 次独立启动，在固定实时节奏样本中测首次稳定短句延迟，**P95 ≤5.5 秒（2026-11-04 预览门槛；原 3 秒保留为未来目标，见 §11）**；分别记录冷/热启动，仍须同时报告应用附加播放延迟与冻结，防止通过拖慢媒体获得表面同步。每个 30 分钟直播案例后 5 分钟的延迟中位数相对前 5 分钟增长 ≤1 秒。准备、故障等待和来源缓冲单独列出。本轮预览允许以固定输入的本地实时回放作为 30 分钟稳定性输入；公网 HLS 30 分钟另列支持矩阵，不因回放通过而标公网通过。
- **可读性**：常规桌面视口最多两行、无裁切、全屏可见；因积压调度导致的不足 0.6 秒连续换页为 0。音频自身短促语句单独标注，按相邻语义合并评审，不能人为拖到后续无关语音。
- **故障与控制**：第 4 节的状态与下一步动作全部可观察；自动恢复次数与等待上限不超预算，“仅播放”和停止之后不再投送新音频；网络恢复后的字幕不会补到错误位置。

首次准备时间在固定本地样本上重复至少 3 次，分别报告冷/热启动和是否已缓存；本轮先建立基线，不承诺固定“8 秒完成”或“零等待”。大文件资源和首次准备时间的公开承诺须另有长文件实测依据。

### 7.4 发布门槛

A01–A10 的首版必验项都有结论和证据，第 7.3 节目标逐项通过，公开支持清单只包含实测来源/格式，且没有未解决的字幕错位、长段倾倒、隐式付费重试、Key 泄漏或无法停止问题。受阻项不能记通过；有发布范围变化时先更新 PRD 与支持说明，再决定是否发布。

## 11. 2026-11-04 PR89 预览验收门槛调整

本节由用户在 2026-11-04 明确要求“修改 spec，然后合入主分支”后写入；优先于前文的旧数值，历史失败与旧目标原样保留，不把本次调整写成通过。

### 证据

- 候选：`027b3254cc56cc7ea58b1e2066958e86481cc6a0`（PR89 squash 合入 main），关键运行时/依赖：Python 3.12、DashScope 2.0.3、真实 Chrome。
- 启动：固定 HLS、真实 ASR、每语 20 次有效启动；中文 P95 **5013.9 ms**、英文 P95 **4470.3 ms**；冷/热、HLS 分片/PCM/进程相关性、采样均有效，0 运行错误。
- 独立复核：中文 provider 首个完整短语在首音频体后 +4274.3 ms，英文 +3272.2 ms；应用显示层只增加 4/26 ms，稳定策略增加 530/1012 ms；即使本地延迟为零仍有 4375.8/3373.6 ms，3 秒在现有 provider 的安全语义下不可达。
- 同步：真实浏览器采集完成（6412 个 50 ms 采样、175 张转场截图、真实音频、0 错误），但评分器因播放期间 9 次短暂停顿、epoch 锚点不足返回 **unknown**；没有 50 句有效偏差样本，不能记通过。
- 长时：中英各 30 分钟固定输入实时回放，0 公开错误、采样有效、无来源缓冲；前后 5 分钟延迟代理增长 -0.044 秒（中）/-0.228 秒（英）。代理非独立声学真值，2 秒以上无字幕区间较多，且结束为观察上限取消而非正常 EOF。
- 完整记录：[PR89 验收缺口复测](2026-11-04-pr89-acceptance-recheck.md)（报告副本）及本机 `notes/pr89-acceptance-20261104/`。

### 决定

1. **启动（预览门槛）**：每种语言 20 次独立启动，首次稳定短句 P95 ≤ **5.5 秒**；保留冷/热、HLS 身份、采样、附加播放延迟和冻结报告。原 3 秒目标保留为未来目标；provider 或模型变化后仍按 3 秒复测，不能用本预览门槛宣称低延迟。
2. **长时（预览门槛）**：中英各至少 30 分钟固定输入实时回放，要求无公开错误、50 ms 采样有效、无来源缓冲、前后 5 分钟延迟代理增长 ≤1 秒；必须报告代理方法、暂停/缺失区间和 cap 取消。公网 HLS 30 分钟仍按来源矩阵单独验收，不因回放通过而标公网通过。
3. **同步（正式门槛，不因预览豁免）**：保持每语 50 句、P95 ≤0.5 秒、最大 ≤1 秒、覆盖 ≥95%。当前 **unknown**；PR89 预览合入不以它为阻塞，但正式发布 #46 必须通过。不得在任何对外材料中写“同步已通过”。
4. **仍然开放/不计通过**：真实公网 30 分钟、独立声学同步、英文快语速参考、关键语义、干净 Windows 与第二设备（用户已排除，不新增承诺）。
5. **发布表述**：本轮只能称“实验预览 / PR89 代码切片”，不是正式首版；README、支持清单和界面说明需保留 5 秒级启动、同步 unknown、公网来源未全部验证的限制。

### 后果

- PR89/main 可以按预览范围合入和部署；#34/#44 的启动与长时稳定性可在本节门槛下记录为“预览通过”，#63/#46 保持开放。
- 不更新正式发布标签，不把 CI 绿灯、回放通过或本机部署当成发布验收。
